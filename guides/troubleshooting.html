Fix the problems that actually happen.

Most plugin problems are version mismatches, duplicate JARs, a config typo or a server that was not restarted. Work from the log first, change one thing at a time, and keep the backup you made before the change.

Updated 5 November 2026 9 min read Support

Start with the log, not the plugin list

The server log tells you whether a plugin failed to load, which class was missing and which file caused the exception. Open logs/latest.log and search for the plugin name or for words such as Could not load, Unsupported, NoClassDefFoundError or Exception.

Read the first error, not the last one. Later lines are often consequences of the first failure. If the server will not start at all, the useful line is usually within the last screen of output before it exits.

Change one thing at a time. If you update Java, replace two plugins and edit a config in the same restart, you will not know which change fixed or caused the problem.

The plugin does not appear in /plugins

Check these in order:

  1. Wrong folder. The JAR must be directly inside the server's plugins/ folder, not in a subfolder and not in the server root.
  2. Nested archive. If you downloaded a ZIP, extract it. A ZIP placed in plugins/ is ignored.
  3. Duplicate versions. Two JARs of the same plugin can prevent one from enabling. Remove the older file.
  4. No restart. Plugins are loaded at startup. Copying a JAR into a running server does nothing until you restart.
  5. Java too old. These builds require Java 17 or newer. An older runtime can fail before the plugin registers.

Version and API errors

A plugin compiled for Minecraft 1.21.x will not run on a 1.20.x server. The console may report an unsupported API version, a missing class or a NoSuchMethodError. Check the compatibility table before changing configs:

PluginSupported Minecraft
UltraTreeFeller 1.1.01.21.x
AutoRefill 1.1.01.21.x
FerKunG Stacker 1.3.01.20.x – 1.21.x

If you run 1.20.x, use FerKunG Stacker and skip the other two until you upgrade the server. Do not edit api-version in plugin.yml to force a load; it may start but fail later with harder-to-diagnose errors.

The server crashes after installing a plugin

  1. Stop the server completely.
  2. Move the newest JAR out of plugins/.
  3. Start the server again.
  4. If it starts, the new plugin is the cause. Check its version and the log entry that names it.
  5. If it still fails, restore the plugins/ folder and world from your backup.

A crash on startup is usually easier to recover from than a corrupted world. That is why the install guide puts the backup before the file copy.

Lag when someone fells a large tree

UltraTreeFeller removes logs in batches. A large tree, or several players felling at once, can briefly exceed what the server can process in a tick.

  • Lower blocks_per_tick from 20 to 10 or 5.
  • Lower max_logs_per_tree from 250 to 100.
  • Keep require_leaves: true so only natural trees are affected.
  • Disable particles or sound if the client effects are part of the stutter.

If the whole server freezes for several seconds, check whether the world is on a slow disk or whether another plugin is also reacting to block breaks. The log and a timing profiler will show more than guessing at config values.

Items are not stacking

FerKunG Stacker only merges items that are eligible under the current config:

  • stack-all: false means only items listed under items are stacked.
  • The item may be in blacklist.
  • preserve-custom-metadata: true keeps renamed, enchanted or lore-tagged items separate, even when the material matches.
  • The drops may be farther apart than stacking-radius.
  • Tools, armour and other unstackable items are never merged.

Test with plain, newly dropped items before changing the radius. Raising the radius to cover a large farm increases the scan area and can cost more than it saves.

AutoRefill does not refill the hand

  • Check enabled: true in plugins/AutoRefill/config.yml.
  • Check whether the item is listed under ignored-items.
  • Confirm the player has autorefill.use; it defaults to true, but a permissions plugin may override it.
  • Make sure there is another matching stack in the inventory. AutoRefill moves items; it does not create them.

After editing the config, run /autorefill reload or restart the server. If the command is not recognized, the plugin did not enable; go back to the log.

Restoring a world backup

  1. Stop the server and confirm it has exited.
  2. Rename the current world folders instead of deleting them, for example world_broken.
  3. Copy the backup world folders back into the server directory.
  4. Start the server and check the console for chunk or region errors.
  5. Join and verify the spawn, inventory and recent builds before deleting the renamed copy.

Restore the matching plugins/ folder too if the backup was taken before a plugin change. A world from a newer Minecraft version may not open on an older server.

Asking for help without wasting time

When you open an issue on the FerNode repository, include:

  • Server platform and exact version, for example Paper 1.21.4 build number.
  • Plugin name and version.
  • Java version from java -version.
  • The first error from logs/latest.log, with any IP addresses or tokens removed.
  • What you changed immediately before the problem appeared.

That is usually enough to identify the cause without a back-and-forth. Never post your hosting password, console access or private server address.
