Plugin settings, commands and permissions.

The reference page for the three FerNode plugins. Defaults below are the values generated on first start in the current 1.1.0 and 1.3.0 builds.

Updated 5 November 2026 7 min read Reference

Where the config files live

Each plugin creates a folder named after the plugin inside plugins/. The file you edit is always config.yml: 

plugins/
├─ UltraTreeFeller/config.yml
├─ AutoRefill/config.yml
└─ FerKunGStacker/config.yml

Stop the server before editing, or change the file and use the plugin's own reload command. YAML is indentation-sensitive: use spaces, not tabs, and keep the existing nesting. A malformed file usually makes the plugin fall back to defaults or fail to enable, so keep a copy before editing.

UltraTreeFeller 1.1.0

UltraTreeFeller activates with SHIFT rather than a command. Hold an axe, press SHIFT five times, then break a tree. The action bar fills while you activate it, and a cooldown prevents immediate reuse.

How activation works

  • required_shift_presses: 5 — number of SHIFT presses needed while holding an axe.
  • cooldown_seconds: 3 — wait time after activation before it can be triggered again.
  • The action bar label and bar characters are configurable with & colour codes.

Config keys

require_leavestrueOnly fells logs that have leaves nearby, which avoids consuming built structures.
leaf_radius6Search radius used by the leaf check.
durability_enabledtrueApplies axe durability while felling.
particle_enabledtrueToggles particle effects.
sound_enabledtrueToggles sound effects.

Reducing lag on big trees

A jungle tree or a large custom tree can contain hundreds of logs. If the server stutters when someone fells one, lower blocks_per_tick to 10 or 5 and reduce max_logs_per_tree to 100. Keep require_leaves: true so player-built log walls are not treated as trees.

Permissions and commands

treefeller.use defaults to true. This build registers no command, so there is nothing to reload with a slash command; restart the server after editing its config.

AutoRefill 1.1.0

AutoRefill watches the player's main hand. When the stack runs out, it pulls the same item from the inventory into the hand. It does not create items and it does not bypass inventory limits.

Config keys

KeyDefaultWhat it does
enabledtrueTurns the refill behaviour on or off.
ignored-itemsempty listItems that should never be refilled automatically.

Example: keep disposable or dangerous items out of the refill:

enabled: true
ignored-items:
  - TNT
  - LAVA_BUCKET
  - ENDER_PEARL

Commands and permissions

FerKunG Stacker 1.3.0

FerKunG Stacker merges nearby dropped items into larger stacks, stabilises them so they stop sliding, and can display the stack amount in the item name. It supports 1.20.x through 1.21.x, unlike the other two plugins.

Config keys

KeyDefaultWhat it does
stacking-radius2.5Block radius searched for matching drops.
max-stack-size9999Maximum items in one stack (2–9999).
stabilize-itemstrueStops items moving sideways when they spawn.
stack-alltrueStacks every stackable item except the blacklist.
blacklisttwo entriesItems excluded when stack-all is true.
itemsexample entriesItems to stack when stack-all is false.
preserve-custom-metadatatrueKeeps items with different names, lore or enchantments separate.
display.enabledtrueShows the amount in the item name.
display.format&b&l{amount}x &f{name}Name format; {amount} and {name} are replaced.

The default blacklist contains NETHERITE_SWORD and DIAMOND_CHESTPLATE. Tools, armour and other unstackable items are never merged even when stack-all is true.

Choosing a radius and stack size

A small radius is easier on the server. 2.5 blocks is enough for a normal drop pile; raising it to 8 or more makes the plugin scan a much larger area on busy farms. A very large max-stack-size is mostly cosmetic, but it can make a single item entity represent thousands of items, so test your farm output and backup before changing it.

Reloading safely

Use the plugin's own reload command when it has one. Reloading a single plugin is predictable; reloading the whole server with /reload is not. A global reload re-runs enable logic for every plugin while the server is live, which can duplicate listeners or leave scheduled tasks pointing at old state.

PluginApply config changes with
AutoRefill/autorefill reload
FerKunG Stacker/fkstacker reload
UltraTreeFellerStop and restart the server
